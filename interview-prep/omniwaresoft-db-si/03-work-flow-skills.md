# 工作流程 → 你要會的事

## 結論先講

**Linux 兩邊都需要，而且 SQL 線一樣重。**  
客戶機房的 EDB／Greenplum／ELK／Mongo 幾乎都跑在 Linux；裝、查 log、看磁碟、重啟、改設定都離不開它。Docker 也多半在 Linux 上。面試說「會 Linux 有加分」＝整份架設／維運工作，不是 NoSQL 專用。

| | SQL（EDB／GP） | NoSQL（ELK／Mongo／Docker） |
|--|----------------|----------------------------|
| 要不要 Linux | **要** | **要** |
| 典型用途 | 裝 DB、改 conf、查 PG log、重啟、磁碟、權限 | 裝叢集、容器、查 ES／Mongo log、調資源 |

差別只在上面跑的是 `postgres` 還是 `elasticsearch`／`mongod`。

---

## 整段流程對技能

```
合約／進場
  → 架環境（或協助客戶架）
  → 設定與驗證
  → 上線
  → MA／health check
  → 版本升級再進場
```

### 1. 進場前／環境準備

| 要會的事 | 新人合理程度 |
|----------|----------------|
| 讀需求：裝什麼、幾台、有沒有 HA／備份 | 能聽懂、會記重點 |
| Linux 基本操作 | 進目錄、編輯檔、權限、查程序、看磁碟／記憶體 |
| 網路概念 | IP、port、防火牆「連不連得上」 |
| 依文件照步驟安裝 | 跟著 runbook 做、卡住會查 log |

### 2. 架設資料庫（SQL 線主軸）

| 要會的事 | 說明 |
|----------|------|
| PostgreSQL／EDB 安裝與啟動 | 服務起得來 |
| 基本設定 | 監聽、連線、`pg_hba.conf` |
| 帳號／權限 | 建 user、最小必要權限 |
| 儲存與目錄 | data 放哪、磁碟別滿 |
| HA／複製／PEM／備份工具 | 名要認得；進階可跟資深一起做 |

### 3. 上線前驗證

| 要會的事 | 說明 |
|----------|------|
| 連線測試 | 本機／應用端連得上 |
| 簡單 SQL | 建表、寫入、讀取正常 |
| 備份跑過一次 | 機制有動 |
| 監控有亮（若有 PEM） | 知道去哪看 |
| 安裝／交接紀錄 | SI 很看文件 |

### 4. MA／Health check

| 常檢查什麼 | 你要懂的 |
|------------|----------|
| 服務是否在跑 | `systemctl`／行程 |
| 磁碟、記憶體、負載 | Linux 資源指令 |
| 連線數、異常／鎖 | 基本 DB 狀態 |
| 備份成功與否 | 備份 log／報表 |
| HA／複製是否正常 | 主備狀態 |
| 慢查詢／空間成長 | 之後再加深 |

### 5. 版本升級再進場

| 要會的事 | 說明 |
|----------|------|
| 照原廠／內部文件 | 先測再正式 |
| 升級前備份、升級後驗證 | 流程紀律 |
| 出問題會看 log、回報、跟同事解 | ownership |

### 6. 軟技能（他們明確說的）

- 態度、ownership、teamwork  
- 願意出差、現場收完  
- 英文技術文件讀得懂

## 學習優先順序

**第一層（現在就要能口述＋有手感）**

1. Linux：檔案、權限、服務起停、看 log、`df`／`free`／`top`  
2. PostgreSQL：安裝概念、連線、user、簡單備份（`pg_dump` 等級先有）  
3. 出問題：服務掛了／連不上／磁碟滿 → 怎麼查  

**第二層（對上 EDB 產品頁）**

4. PEM／EFM／Barman／Migration／xDB 各解決什麼  
5. Health check 會檢查哪些項目  

**第三層（進案再加深）**

6. HA、複製、真正升級演練、Greenplum／WarehousePG  

---

## 一句話總結

工作要會的是：**在 Linux 上把資料庫裝起來、驗證上線、定期檢查、升級時再進場**；EDB 產品知識疊在這上面。  
Linux = SQL／NoSQL 共用必修，往 SQL／EDB 走一樣天天用。
